MLOps Platform — End-to-End Flow

This page explains the full lifecycle of your app from data to production. It is the conceptual flow only (no code), so you can understand what happens and why.

Training: Kubeflow Pipelines Registry: MLflow Serving: FastAPI Monitoring: Prometheus + Grafana Drift: Evidently

1) Source of Truth

The app uses a single configuration source. Every service reads the same env variables so behavior stays consistent across local, CI, and Kubernetes.

Settings → ConfigMap / .env

2) Training Orchestration

Kubeflow Pipelines runs a four-step workflow: load data, train a model, evaluate it, and register it when quality is good.

KFP → load → train → evaluate → register

3) Model Registry

MLflow stores models as versions. When a model meets the threshold, it is promoted to the “champion” alias used by the API.

MLflow Registry → champion alias

4) Inference Service

FastAPI loads the “champion” model on startup. If the registry is unavailable, it falls back to the local .pkl model.

FastAPI → /predict /batch /explain

5) Logging & Metrics

Each prediction is stored in SQLite for drift checks. Prometheus scrapes metrics for alerts and Grafana dashboards.

SQLite + Prometheus + Grafana

6) Drift Detection

Evidently compares recent production data with the training baseline to detect drift. If drift is found, you trigger retraining.

Evidently → Drift Report

Start-to-End Steps You Perform

1

Bring up MLflow (registry + tracking)

This is the central model store. The pipeline will register models here and the API will load from here.

2

Run the Kubeflow pipeline

KFP trains, evaluates, and (if accuracy is good) registers the model as the “champion” alias.

3

Deploy the API (Kubernetes or Docker Compose)

The API reads the “champion” model. If MLflow is unreachable, it uses the local fallback model.

4

Send prediction requests

Clients call /predict or /batch. The API logs each prediction and exposes metrics.

5

Monitor and alert

Prometheus collects metrics and alert rules fire when errors or latency are high. Grafana visualizes everything.

6

Check drift and retrain when needed

Drift reports guide when to trigger another Kubeflow run to update the model.

Tip: If KFP cannot reach MLflow, model registration fails. Make sure MLflow is reachable from inside the cluster (a Service) or pass a reachable MLflow URL to the pipeline.
